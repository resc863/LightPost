# LightPost 테스트 계획

첫 번째 수직 슬라이스에서는 콘텐츠를 잃거나 초안을 외부에 노출하는 문제가 가장 위험하므로 저장소와 HTTP 경계를 함께 검증합니다.

| ID | 영역 | 시나리오 | 기대 결과 |
|---|---|---|---|
| LP-UNIT-001 | Markdown | 제목과 강조가 포함된 Markdown을 변환 | `<h1>`과 `<strong>` HTML이 생성된다 |
| LP-UNIT-002 | URL | 제목을 slug로 변환 | 공백·구두점이 제거되고 안정적인 URL 조각이 생성된다 |
| LP-STORE-001 | 저장소 | 발행 글과 초안을 함께 저장한 뒤 공개 목록 조회 | 발행 글만 반환된다 |
| LP-HTTP-001 | 글 상세 | 발행 글의 slug로 GET 요청 | 200 응답과 제목·본문 HTML을 반환한다 |
| LP-HTTP-002 | 글 상세 | 초안의 slug로 GET 요청 | 404 응답으로 외부 노출을 막는다 |
| LP-HTTP-003 | 관리자 API | 세션 쿠키 없이 글 생성 요청 | 401 응답을 반환한다 |
| LP-HTTP-004 | 관리자 API | 올바른 세션 쿠키로 글 생성 요청 | 201 응답과 생성된 글 JSON을 반환한다 |
| LP-HTTP-005 | RSS | 발행 글과 초안을 함께 저장한 뒤 RSS 조회 | RSS에는 발행 글만 포함된다 |
| LP-HTTP-006 | 검색 | 같은 검색어의 발행 글과 초안을 조회 | 발행 글만 검색 결과에 포함된다 |
| LP-HTTP-007 | 입력 검증 | 관리자 API에 빈 제목·본문 전송 | 400 응답을 반환하고 저장하지 않는다 |

## 실행 명령

```powershell
$env:CC = "clang-cl.exe"
cargo test
```

SQLite의 `bundled` 빌드는 Windows에서 C 컴파일러가 필요합니다. 로컬 개발 환경에서 `cl.exe`가 정상적으로 등록돼 있으면 `CC` 지정은 생략할 수 있습니다.

## 다음 단계의 테스트

- 태그 URL이 정확한 태그만 반환하는지 확인한다.
- 잘못된 JSON을 400으로 거부하는지 확인한다.
- 실제 파일 기반 SQLite를 열고 재시작 후 글이 유지되는지 확인한다.
- 정적 자산과 모바일 레이아웃은 브라우저 기반 스모크 테스트로 확인한다.
